# Журнал интеграции

Компонент `sandbox:integration.logs` доступен участникам активной группы `АЭС` (символьный код `aes`) на `/local/pages/integration-logs.php`.
Классы `Utils\IntegrationLog\Parser` и `Storage` находятся в `local/utils/IntegrationLog` и зарегистрированы в `local/php_interface/init.php`.
`bootstrap.php` позволяет запускать тест парсера без ядра Битрикса.

## Установка и проверка

1. Применить миграцию `Version20261026150000` через Sprint Migration. Она создаёт highload-блок `IntegrationLog`, таблицу `integration_log`, семь полей, уникальный индекс ключа импорта и индексы даты и уровня. Повторный запуск дополняет отсутствующие поля. Автоматический откат отключён, чтобы сохранить журнал.
2. Запустить тест парсера:

```powershell
docker exec -e XDEBUG_MODE=off module-php php /var/www/html/local/tests/integration-log-parser.php
```

3. Запустить импорт, передав существующий путь к источнику **внутри контейнера**:

```powershell
docker exec -e XDEBUG_MODE=off module-php php /var/www/html/local/cron/import-integration-logs.php /path/in/container/source.log
```

Файл источника не включён в проект. Разместите или смонтируйте его вне публичного корня сайта и замените путь в команде. Без аргумента импорт сообщает правильный формат запуска.
4. Повторить импорт: уже загруженные строки пропускаются.
5. Открыть `/local/pages/integration-logs.php` под пользователем группы `aes`. Пользователь вне этой группы получает HTTP 403; администратор без членства в `aes` также не имеет доступа.

## Cron

В контейнере с PHP и доступом к файлам сайта используйте команду, заменив путь источника:

```cron
0 3 * * * php /var/www/html/local/cron/import-integration-logs.php /path/in/container/source.log >> /var/www/html/local/var/integration-log/cron.log 2>&1
```

Пример предполагает запуск внутри контейнера, не в Windows Task Scheduler. Системное расписание скрипт не создаёт. Уточните часовой пояс cron и запускайте от пользователя сайта с правами чтения источника, доступа к БД и записи в `local/var/integration-log`.

Коды завершения: 0 — успех; 1 — ошибка окружения, БД или блокировки; 2 — есть некорректные либо незавершённые строки.
Параллельный запуск блокируется общим `local/var/integration-log/import.lock`.

## Формат

UTF-8, одна запись на строку, последняя строка также должна завершаться переводом строки:

```text
2026-10-26 12:00:00 [info] sandbox.orders: Синхронизация запущена
2026-10-26 12:00:05 [ERROR] sandbox.orders: Ответ сервера: HTTP 500
```

Уровни: `info`, `warn`, `error`, `fatal`, `debug`; регистр не важен. Поддерживаются BOM, LF, CRLF и двоеточия внутри сообщения. Дата проверяется строго; timezone PHP CLI должен совпадать с timezone сайта.
IP и автор отсутствуют в исходном формате и сохраняются как «не указан».
Ограничения: строка — 1 МиБ, сообщение — 60000 байт, ID модуля — 255 байт.
Незавершённая строка откладывается до следующего запуска. Ошибки формата не останавливают следующие строки; ошибки БД останавливают импорт. Содержимое логов в stderr не выводится.

SHA-256 вычисляется по абсолютному пути, номеру строки и тексту. Одинаковые записи на разных строках сохраняются отдельно; повторный запуск неизменённого файла не создаёт дублей.
Источники предполагаются дописываемыми: переименование, перестановка и перезапись строк могут привести к повторному импорту. Для ротации нужен постоянный ID события и отдельная стратегия импорта.

## Интерфейс и доступ

Фильтры: уровень, модуль, IP, автор, даты и время. Фильтры применяются в SQL до пагинации. Время задаётся как ЧЧ:ММ или ЧЧ:ММ:СС и применяется к каждому дню диапазона; диапазон через полночь не поддерживается.
HTML в сообщениях отображается как текст. Журнал не кешируется.

Служебные каталоги закрыты `.htaccess` для Apache. Если статику отдаёт nginx напрямую, нужны соответствующие правила его конфигурации:

```nginx
location ^~ /local/var/ { return 404; }
location ^~ /local/cron/ { return 404; }
location ^~ /local/tests/ { return 404; }
location ^~ /local/utils/IntegrationLog/ { return 404; }
location ^~ /local/php_interface/migrations/ { return 404; }
```

Не размещайте реальные источники логов в публичных каталогах.

## Экспорт CSV

Для выгрузки пользователь должен состоять в двух активных группах: `aes` и `integration_log_export`. Создайте вторую группу в административной панели Битрикса и добавьте сотрудников, которым разрешена выгрузка. Администратор автоматически это право не получает. Отсутствующая или неактивная группа запрещает выгрузку.

Ссылка «Скачать CSV по текущим фильтрам» выгружает все результаты применённых фильтров, независимо от страницы. Обработчик `/local/pages/integration-logs-export.php` повторно проверяет права; отказ — HTTP 403, неверные фильтры — HTTP 400.

Формат: UTF-8 с BOM, разделитель — точка с запятой. Потенциальные формулы получают префикс-апостроф. Записи идут по убыванию ID (порядок импорта), тогда как таблица сортируется по времени события. Чтение идёт порциями по 500 без OFFSET, новые записи после начала выгрузки не включаются. CSV сначала формируется во временном файле PHP: требуется свободное место на диске и достаточный таймаут PHP/веб-сервера; фоновая выгрузка не реализована.

Проверка прав и CSV без ядра Битрикса:

```powershell
docker exec -e XDEBUG_MODE=off module-php php /var/www/html/local/tests/integration-log-export.php
```

Ручная проверка: пользователь только в `aes` видит журнал без ссылки, прямой запрос экспорта получает 403. Пользователь в обеих группах скачивает CSV; проверьте фильтры и выгрузку более 500 записей, а также пустую выборку.
